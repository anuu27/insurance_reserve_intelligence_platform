# Mathematics

## Term-Life Reserve Equation

The initial implementation targets a term life insurance reserve process governed by:

```text
dV/dt = rV + P - μ(S - V)
```

Where:

- `V(t)` is the reserve at elapsed duration `t`
- `r` is the interest rate
- `P` is the premium inflow rate
- `μ` is mortality intensity
- `S` is the sum assured

## Interpretation

The reserve changes through three forces:

1. Asset accumulation: `rV`
2. Premium inflow: `P`
3. Death benefit outgo net of reserve release: `-μ(S - V)`

The mortality term reduces reserve growth because death triggers claim outgo `S`, partially offset by existing reserve `V`.

## Boundary Condition

For term insurance, the terminal reserve at maturity is zero:

```text
V(T) = 0
```

This is the boundary condition used by both the numerical solver and the PINN loss.

## PDE Residual Derivation

Define the residual function:

```text
f(t) = dV/dt - rV - P + μ(S - V)
```

If the reserve function exactly satisfies the Thiele equation, then:

```text
f(t) = 0
```

The PINN minimizes the residual over sampled collocation points in the policy state space.

## Data Loss

Let `V_PINN` be the reserve predicted by the network and `V_classical` the reserve generated by the classical solver. The supervised data term is:

```text
L_data = MSE(V_PINN, V_classical)
```

## PDE Loss

The residual-based physics term is:

```text
L_pde = MSE(f, 0)
```

Automatic differentiation computes `dV/dt` directly from the network output with respect to the time input.

## Boundary Loss

The terminal reserve constraint is enforced with:

```text
L_boundary = MSE(V(T), 0)
```

## Regularization Loss

Optional L2 regularization on network parameters:

```text
L_reg = Σ ||θ_i||²
```

## Total Loss

The training objective is:

```text
L =
lambda_data * L_data +
lambda_pde * L_pde +
lambda_boundary * L_boundary +
lambda_reg * L_reg
```

All lambda weights are sourced from YAML configuration.

## Variable Summary

- `t`: elapsed duration
- `x`: age at policy inception
- `x + t`: attained age
- `r`: interest rate
- `P`: premium
- `μ`: mortality intensity
- `S`: sum assured
- `θ`: neural network parameters
- `π`: macroeconomic regime or scenario descriptor

## Why a PINN Here

The reserve function is smooth, constrained by financial and biometric dynamics, and valuable in differentiable form for sensitivities and optimization. A PINN is appropriate because it learns from both data and governing equations, reducing the chance of purely data-driven extrapolation errors.
